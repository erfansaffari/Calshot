# Calshot design system and interaction contract

## Source and hierarchy
The optional local Calshot.html at the project root contains the approved reference boards: home, notch, syllabus review, clarification, partial failure, transfer, calendars, history and settings. It is ignored by Git and is not required to build or run the app. This tracked document is the interaction contract when that local reference is unavailable. Follow the translucent desktop workspace, the color rule below, compact left navigation, readable central conversation and optional right source panel. Adapt fixed mockup dimensions to a real resizable window. Do not ship the reference's mock data or simulated writes.

WebUI/src/tokens.css is the implementation source for color, spacing, radii and focus tokens. Shared controls live in WebUI/src/components. Prefer Radix accessible primitives for overlays, native form controls and Lucide icons; avoid importing an unrelated component library theme.

## Color rule
Every component follows this rule. It overrides colors in the older reference boards.
- **The window is real glass.** The windows and desktop behind Calshot stay visible, blurred, through the whole app. Never paint a decorative or opaque background behind the content. Dark appearance is black glass with a slight navy depth; light appearance is its silver counterpart. Surfaces, lines and text never lean toward any hue except that navy.
- **The menu has no panel.** The sidebar is the bare window glass with no fill, border or blur. The workspace is the one framed surface: a hairline border, a light top edge and a thin dark tint for legibility. The current page shows a glass disc around its icon with brighter text, not a filled row.
- **Blue is the accent.** `--primary` fills primary actions in the workspace, the send button, checked controls and on switches. `--accent` colors links, focus rings and progress. Capture is a quiet glass pill in the menu so the menu holds no bright block.
- **Color gradients live only in ambient.css**: the Assistant home orb. Anywhere else a gradient may only be the white specular sheen of the material.
- **Sent messages are glass** like any other surface, set apart by alignment instead of a color block.
- **Components never pick colors or materials.** Use the semantic tokens (`--surface-subtle`, `--surface`, `--surface-raised`, `--surface-inset`, `--line`, `--text`, `--muted`, `--primary`, `--accent`). glass.css turns those tokens into glass, so a new component is glass by default. Anything floating over other content uses `--surface-overlay`.
- **Other color must carry meaning.** Allowed: danger, warning and success states; source-calendar colors and the red today marker; the voice pill's listening, thinking and speaking states; the small icons on Assistant home suggestion chips; the black camera bezel. Screenshots are never recolored.

## Motion
Surfaces respond on press (scale .97, 100 ms). Home content and new messages rise 8 points and fade in (critically damped feel, no overshoot); dialogs materialize with a slight scale. Motion uses only transform and opacity, never bounces, and is removed by Reduce Motion. Repeated snapshots must not restart it.

WebUI/tests/color-rule.test.tsx enforces the checkable parts of this rule.

## Type and sizes
Calshot is a compact Mac tool, so it follows the density of macOS and of Codex and T3 Code: a 13-point interface with 14-point reading text. WebUI/tests/color-rule.test.tsx enforces the type sizes and weights.

Controls are 32 points, or 28 in toolbars and rows. The workspace header is 52 points. Corner radii are 4, 8, 12, 16 and 20, or fully round for pills.

## Liquid Glass appearance
The desktop window uses a native NSGlassEffectView with a neutral tint on macOS 26 and NSVisualEffectView on earlier supported releases. Web surfaces share the material in WebUI/src/glass.css: the framed workspace, composer, toolbars, menus, buttons, switches, selections, cards, messages and expanded notch detail. Only the floating control layer uses backdrop blur. The camera bezel remains black. Do not apply a separate blur to every row or use transparency to communicate state.

Settings → General → Liquid Glass offers an enable switch, Window opacity (35–100%, default 35%), Surface blur (0–40, default 24) and Surface contrast (0–100%, default 50%). Drafts preview within the settings sample; Apply appearance validates and persists the complete choice natively on this Mac. Blur controls web surface blur; the system owns the native window effect. Reset to defaults is a draft until applied. Failed saves keep the draft and a persistent inline error. Saved material preferences do not sync between devices. macOS Reduce Transparency and Increase Contrast override glass with solid surfaces without changing the saved choice; motion remains governed by Reduce Motion. The browser preview has a plain gray backdrop because it has no desktop behind it.

## Layout
- Sidebar: Assistant, Calendar, Tasks, History, Settings. Outside Calendar, the expanded sidebar shows Up next: a bounded, independently scrolling glance at up to three personal calendar events in the next seven days and three open tasks, prioritizing today and upcoming deadlines, then overdue work, then undated tasks. Short windows show the first event and first task; section-header actions open the full lists. Omit completed/archived tasks and duplicate published task-deadline events. Keep source calendars visible, ongoing/all-day events explicit, and partial source failures distinct from an empty agenda. Reuse native read-only calendar snapshots and existing Calendar/Tasks routes; sidebar rows never save or complete anything. Refresh after calendar content/session changes, on manual retry and every five minutes while visible. Calendar retains its mini month and source-calendar visibility controls. Preserve calendar readiness, Capture and collapse; navigation and capture stay fixed while Up next scrolls. Use bare glass, semantic tokens and quiet rows rather than nested cards.
- Conversation: header, scrollable messages/questions/review/results, composer anchored below. The source is contextual and collapses at compact widths; it must not crush the conversation.
- Review rows are compact; show details progressively. Keep the approval footer visible inside bounded review lists. Show before/after for changes, source → destination for moves, exact event details for deletes.
- Minimum native window 920 × 650. Verify at that size and 1440 × 900. Long names wrap; no horizontal page scroll. Never hide critical actions behind hover.

## Error placement
| Failure | Placement | Recovery |
| --- | --- | --- |
| Invalid input | Beside the field in its editor | Explain the correction; preserve unsaved input |
| Unresolved event | On the proposal row | Edit relevant details; cannot approve yet |
| Duplicate | On the proposal row, with comparison | Keep existing or deliberately allow a new copy |
| Calendar write | On affected row plus batch summary | Retry only failed rows; preserve receipts |
| AI/network | In the current conversation | Retry, Stop, or choose an explicit service in Settings |
| Account/permission | On account/permission card; task notice if blocking | Reconnect or open the appropriate system setting |
| Bridge/startup | Persistent workspace alert | Reload frontend or open native settings/recovery |
| Interrupted transfer | In transfer result | Explain copy/original state; never silently copy again |

User-facing errors explain impact and next action. Raw HTTP/tool details may appear under Details. Never show credentials or raw request bodies.

## Chat and agent

Day agenda questions use get_agenda with today, tomorrow or an explicit YYYY-MM-DD date. Native code computes timezone-aware midnight boundaries from a fresh clock, including DST days. The agenda includes free/transparent and all-day events; incomplete coverage cannot establish that a day is empty. search_events query remains a literal title/notes filter, and its results identify that filter. Voice refreshes trusted clock guidance before each spoken response without requesting an extra reply. Screen frames remain optional untrusted evidence, never the task itself; late speech-stop notifications cannot start a second screen-only response. Actual voice tool arguments/results are saved with that conversation, retaining shared-source privacy exclusions and never replaying writes on restore.
Display streamed text and meaningful progress, not tool JSON. Questions have up to six wrapped choices plus an alternate typed answer and Cancel. Bind answers to question IDs. Questions and approvals remain in the current conversation. Avoid repeating an already clear destination question. The composer can answer an outstanding question; other commands must not bypass a pending approval.

The calendar agent follows a decision order: understand the requested outcome, reuse clear context, read missing calendar facts, prepare useful review rows, then ask only for a blocking unanswered choice. Reuse the selected writable destination when none is named. Target initial edit/delete searches to the requested event and dates; respect native target-clarification requirements. Relative dates use the supplied clock and timezone; an unanchored month/day still needs its year resolved. See [agent prompt evaluation scenarios](AGENT_PROMPT_EVALS.md) for expected traces and the limits of scripted tests.

A broad agenda search must not leave a target permanently ambiguous. A focused nonempty query returning one match with no source errors or truncation resolves that earlier ambiguity. Voice reuses spoken clarifications and never calls the unavailable question-card tool. When a voice edit or deletion still has competing targets, nothing is written and no review opens: the tool returns the matches with their day and time, the agent asks aloud which one, and that target becomes eligible for the saved grant only after the user has spoken again.

A month and day the user types or says without a year ("Nov 12") is saved for its next occurrence and never asks for the year; numeric dates such as 11/12 and dates read only from a screenshot still do. Reviews with missing years expose a labelled year field and Confirm year action. Native validation requires the current review token and an integer year from 1900 to 2200, updates only unresolved rows in the approval scope, and retains other ambiguities. Confirmation never writes an event or approves the batch. Invalid dates such as February 29 in a non-leap year remain unresolved with an actionable error. Multi-day all-day spans are preserved. An unambiguous year in native user/answer text can settle a model-inferred year; a model-generated year or screenshot text alone cannot override the inferred flag. Typed chat retains its question-card path; cancelled targets and replacement sessions remain fenced.

Voice never asks for a year. A month and day without a year takes its next occurrence (today included), also when it came from the screen; a year visible in the source or said ("next year", "'28") stands as read. A start without an end takes the user's usual length for that kind of event from the calendar profile, else one hour; "10 to 1" ends the next day. A missing time, title or day is asked aloud, never opened as a review. An event already on the calendar is said aloud and not added again. Transcription can finish after the model replies, so a spoken create waits up to three seconds for the transcript. Guest, repeating and screenshot-import rows, and every row when Autonomy is off, still open the notch review; while it is open further writes are refused without touching its rows, and a single year the user says fills in its unconfirmed rows without approving. The review's destination control works during voice. Escape in a field leaves the field, not the voice session. A quick tap of the voice key ends voice and keeps an open review. Return does nothing for 500 ms after the review changes.

Saved changes appear as a Done list with Undo: in the notch for ten minutes after they are saved (dismissible), and under Up next in the sidebar for a day. Each row shows the change, day and time, calendar, and its own error beside it; a row already undone shows Undone. Undo is a native reverse change from the receipt, validated by the list token, applied once, and never offered for events with guests or repeats.

Calendar views never blank to reload. A refresh keeps the events on screen and only the refresh control shows progress; returning to one of the last six ranges shows its recent copy at once while it refreshes; only a range with nothing loaded yet shows loading. Native reads every calendar in parallel. Calendar execution invalidates visible browser data through a native content token, including partial or uncertain outcomes; the UI refreshes the current range from native readers and never infers event changes from assistant prose. Starting or ending voice and starting a capture do not refresh it. A read begun before a calendar change cannot replace a newer view; event selection handles stay valid for the events on screen while a refresh runs.

Voice never locks the app. While voice is on, everything keeps working except actions that would replace or rewrite the voice conversation (another assistant run, restoring or deleting history, account history sync) and changing shortcuts; those say "Finish talking first". Typing while voice is on continues the same conversation and is answered aloud. Capture ends voice, keeping completed changes, and starts the screenshot at once.

Returning to Assistant opens the newest message. While the conversation stays open, incoming messages respect a user reading older turns.

Voice audio startup yields between up to four fresh graph attempts (200, 400 and 800 ms delays) for transient device/format/graph failures after microphone permission. Permission denial is never retried. Stop or a replacement session fences every later attempt; no delayed connection or microphone reopening is permitted. Voice-processing failure falls back to a fresh ordinary graph. Hardware configuration changes use the same bounded recovery and discard stale graph notifications. Validate input, tap and output formats separately. Preserve an open review when audio fails. Show permission failures beside a microphone-privacy route, and device/format failures beside a token-validated Sound settings route in the notch and Voice settings. Screen Recording remains optional for voice and does not establish microphone availability.

## Global shortcuts
Capture and voice shortcuts change in Settings, and capture also in onboarding. The control only starts or cancels listening: WebKit does not focus a clicked button, so native code reads the key press through a local key monitor, and builds the label from the keys. A shortcut needs ⌃ or ⌘; ⌘ with one key alone is refused, and the key must be a letter, number, symbol, Space or function key. The voice shortcut may instead be modifiers alone, ⌃ with at least one more such as ⌃⌥, chosen by pressing and releasing them. It is read from the modifier state with no extra permission, presses after a 0.18-second hold, and is ignored once another key joins, so combinations like ⌃⌥← keep working in other apps. Capture always needs a real key. A choice is refused when it matches the other shortcut, Calshot's fixed ⇧⌘K Quick Menu, an enabled macOS shortcut, or when macOS rejects the registration. The label and saved value change only after macOS accepts the shortcut. A refusal stays beside the control with the shortcut still in use, and listening continues until another key, Esc or Cancel. A saved shortcut macOS won't run reports the same way, and the sidebar and menu bar stop advertising a capture shortcut that is off. Listening turns both global shortcuts off, so it ends when the control goes away, the page changes, the recording window loses focus, Calshot hides or loses focus, voice starts or a capture begins. Shortcuts cannot change during voice. Registering one shortcut never re-registers the other, so a held voice key keeps its release.

The backend's validated tools include get_agenda, search_events, read_screen_text, ask_user, create_events, update_event, delete_event and move_events. Improve prompts and tools only with tested contracts. Calendar data and screenshots are untrusted content, not instructions. Extract all relevant dated activities, including appointments, meetings, classes, shifts, travel and deadlines. Use explicit headings and prior answers before asking; group essential questions and keep incomplete rows in the review rather than blocking the batch. Ask only for necessary ambiguity; use tools for facts. Never invent calendar availability, missing values or write success.

Keep expanded content mounted through closing, clip it to the animated shell, fade new content without moving button hit targets, and use immediate transitions for macOS Reduce Motion. Notch controls must respond to the first deliberate click even when another app is active; hover never activates or steals focus. Moving outside the actual panel zone collapses it after the leave grace, including after clicking, typing, capture or a shortcut open with the pointer already outside; keyboard focus and active voice must not pin it open. Hit testing follows the visible panel and its current target bounds, never an invisible previous size. Background questions, approvals, voice updates and layout updates never open the panel. Activity notifications expire after four seconds even when a review, question or error remains pending; repeating the same task snapshot never extends that lifetime. Hover restores access to the pending task without cancelling or approving anything. Respect display safe areas, multiple displays, keyboard focus and reduced motion.

## Distributed setup

Google Calendar connection uses Calshot’s registered desktop OAuth client with native PKCE and loopback/state validation. A private-source, authenticated stateless exchange keeps app registration credentials on the server; provider access/refresh tokens return only to Swift and stay in Keychain. Consumer onboarding, Settings and native recovery never ask for Google client IDs or secrets. Offer Internet Accounts as an explicit alternative; explain enabling Calendars and refreshing, and reuse the existing EventKit connection. Preserve existing local/custom account decoding; connecting a calendar never changes Calshot account identity. Cancellation and account changes invalidate pending exchange results.

Screen Recording setup opens the macOS privacy pane with a small native helper containing a draggable file URL for the running app, Show in Finder, Open Settings and Check access. Access status comes from CGPreflightScreenCaptureAccess; dragging does not grant access. Explain the switch, + fallback, quit/reopen and removal of stale entries after ad hoc updates. Reuse this route in onboarding, workspace errors, settings and notch.

The Screen Recording helper is a compact Calshot panel that follows System Settings without requesting Accessibility access. It hides while another app is in front, closes when Settings closes, and pauses tracking during a native app-file drag. Show in Finder and Open Settings remain available for keyboard/manual setup. Its native palette reads the packaged shared CSS tokens. PermissionFlow-derived interaction code retains its MIT notice.

## Tasks
Tasks is a separate sidebar section and page. Preserve the approved Calendar page, timetable, toolbar and event details. Do not add a task panel or replace the calendar. The Tasks page uses shared tokens and controls, native account-scoped storage and current task tokens. Manual ordering changes rank only; completion and archive keep historical provider deadlines and cancel local task reminders. Archived items can be restored. The Assistant home shows only a compact read-only task summary; its rows and View all/Open Tasks navigate to Tasks and never send task write commands. The editor reveals details progressively, and the sidebar item order is stable.

Date-only tasks need no time. Dated tasks default to publishing one all-day, free/transparent deadline in the chosen writable calendar, with any exact due time retained in the title, notes and task. An explicit Tasks-only choice keeps dates as task metadata and writes no calendar event. Add to Tasks on an existing event records an exact source link, distinct from a Calshot publication receipt; completing or editing that task never alters the source event. Saving a dated task in the editor publishes, updates or removes its deadline directly, as the editor states before saving; only a real receipt confirms publication. Failures keep the task with a visible pending deadline and a row-level Try again (Add anyway for a duplicate). Delete asks once; removing the deadline entry is a separate unchecked choice. Linked edits use the original receipt and source Mac; never create a replacement merely because the original cannot be read. Calendar review edits retain the one-day deadline contract. Mac reminders require an explicit alarm choice, notification permission and an explicit time for date-only tasks.

The agent uses create_tasks and list_tasks for requested assignments/to-dos and actual task reads. Internal task-save receipts are distinct from approved calendar receipts. Undated or unresolved-year tasks remain in Inbox with evidence; scheduled classes and exams still use calendar event tools. The website reuses the Tasks page read-only with an explicit Mac handoff. Account sync never executes calendar proposals. Conflicting task edits require an explicit Keep both action. Smart planning, task sharing, estimates and web task editing are deferred.

Task actions and permissions. A task change requested in a conversation (link a selected event, edit, complete or reopen, archive or restore, add a task without a new calendar deadline) either saves immediately because the user turned that action on in Settings → Privacy & permissions → Task actions, or opens one short task-only review inside the current conversation or notch. The review shows the real task title, before → after values or the selected event, states that the calendar is not changed, and offers Cancel and a labelled confirm button. It is separate from the calendar review, never reuses its approval token or footer, and Cmd+Enter confirms only this visible review; Escape never approves. Twelve rows scroll inside a bounded list that is reachable by keyboard. After confirmation the button shows Saving and ignores repeats. Stop, New task, sign-out or an account change cancel the pending review once and remove its buttons; a stale click is rejected next to the review and leaves it usable if still current.

Results appear immediately as a concise Task result card built only from native task receipts: Saved, Already in Tasks, Not saved (with the reason beside that task), Stopped or Not allowed. Rows save one at a time, so a partial result is shown honestly and saved rows are kept. Never show success before the task file has been persisted.

Settings → Task actions lists Add tasks, Add calendar events to Tasks, Edit tasks, Complete or reopen tasks and Archive or restore tasks, each off until the user turns it on and presses Save task permissions. A choice applies only to requests the user makes on this Mac, for 7, 30 or 90 days, within a stated per-request and per-hour limit; larger requests return to review, and approving that review may exceed the limit for that exact request. Saved permissions apply only to requests the user typed; a task change from a screenshot-started run always shows the review. Choosing a period for actions that are already on renews them; turning on another action never extends the others. The section says that nothing syncs between Macs, and that Calshot never changes tasks in the background. A permission store error stays visible here and pauses assistant task changes and automatic calendar saves. Account sync never carries these choices. Publishing a deadline stays in review.

Settings → Calendar, in the same Privacy & permissions group, lists Add new events, Edit event details, Delete events and Move events. The Autonomy switch turns all of them (and the task actions) on together for every writable calendar for a year, renewing while on; it starts on by default, and turning it off returns every change to the review. Events with guests, repeating series and screenshot imports are shown as Always asks and have no switch. A saved grant applies only to a request the user typed or spoke, within the per-request and per-hour limits. A fully resolved row (confirmed year, unambiguous date, start and end or an explicit all-day, title, no duplicate, no guests, not recurring) saves immediately through DirectCalendarWriter and reports its own receipt; a delete or move saves immediately for one searched, confirmed, non-repeating event without guests. Anything unclear, ambiguous, outside those calendars, or over the limit stays in the calendar review, including every row from a screenshot-started run. Rows apply independently. Saying "undo" reverses saved changes through the same path and reports each reversal's receipt; a restored deleted event is a new copy. Nothing runs in the background.

There is one ongoing chat. Typed requests, voice and screenshots all continue it; the sidebar has no list of separate conversations and there is no New task button. History shows that single conversation; deleting it also deletes the earlier conversations that were merged into it.

AI context continuity. Native code supplies bounded recent conversation to both typed chat and voice, reserving conversational space separately from large historical tool outputs. Voice loads history and saved preferences as context data before its first response, and restores current history after reconnect without issuing a new user request or replaying any tool. Both modes expose the read-only, run-scoped `get_conversation_context` tool to search the account's retained main transcript (currently up to 600 stored turns, including tools); retrieval returns bounded chronological excerpts and clipping/coverage metadata. User answers from native question controls count as conversational input. Shared-friend turns and raw tool payloads are excluded from conversation retrieval. Context does not grant write authority or settle native date/year validation; current facts and saved outcomes come from calendar/task tools and receipts. Missing retained history is reported honestly, never reconstructed as fact.

Voice screen context belongs to one spoken turn: clear previous OCR before obtaining a fresh frame, including blank/failed captures. Screen text and historical/calendar data remain untrusted evidence rather than system instructions. Calendar snapshots carry their read time and coverage, refresh after calendar content changes or a short time interval, and mark the earlier snapshot stale while replacement data loads. Live calendar tools remain authoritative for incomplete, missing or stale snapshots. Switching accounts, stopping or reconnecting fences late context and tool results from the old run/connection.


Shared-copy freshness: when the source Mac app is closed, display the last authorized copy with its last-sync time and a persistent stale/coverage warning. Keep returned events visible; do not describe a stale-but-readable copy as a load failure or call an empty stale range free time. Current read/access errors remain errors. Sharing metadata and the displayed range refresh when syncedAt, stale state or a publication error changes. Incoming metadata refreshes during tasks; publication still waits for idle and remains limited to existing explicit sharing grants. Sharing refresh runs independently of history sync, so a slow history request cannot starve it. No recipient refresh can fetch new source-Mac events while that app is closed.

Settings → Privacy & permissions → AI context exposes an explicit, read-only local context viewer. View/Refresh takes a dated native snapshot of approved unexpired memories, bounded retained conversation, readable calendar sources, the last sent voice calendar snapshot with freshness, captured screen text, receipt-backed changes and current task titles. It never captures a screen, fetches events or contacts AI. Explain that this is available context, not a complete model prompt; show clipping/retention and empty/error states. Exclude raw tool payloads, credentials and marked shared-friend turns. Keep text selectable in bounded, keyboard-accessible disclosures. Hide clears the inspection; leaving Settings or changing account clears it as well. Memory editing stays in the existing Memory controls.
