# Calshot design system and interaction contract

## Source and hierarchy
Calshot.html contains the approved reference boards: home, notch, syllabus review, clarification, partial failure, transfer, calendars, history and settings. Follow their light translucent desktop workspace, blue primary actions, compact left navigation, readable central conversation and optional right source panel. Adapt fixed mockup dimensions to a real resizable window. Do not ship its mock data or simulated writes.

WebUI/src/tokens.css is the implementation source for color, spacing, radii and focus tokens. Shared controls live in WebUI/src/components. Prefer Radix accessible primitives for overlays, native form controls and Lucide icons; avoid importing an unrelated component library theme.

## Layout
- Sidebar: Assistant, Calendar, History, Settings. Calendar replaces recent tasks with a mini month and source-calendar visibility controls. Preserve calendar readiness, Capture and collapse.
- Conversation: header, scrollable messages/questions/review/results, composer anchored below. The source is contextual and collapses at compact widths; it must not crush the conversation.
- Review rows are compact; show details progressively. Keep the approval footer visible inside bounded review lists. Show before/after for changes, source → destination for moves, exact event details for deletes.
- Minimum native window 920 × 650. Verify at that size and 1440 × 900. Long names wrap; no horizontal page scroll. Never hide critical actions behind hover.

## Error placement
| Failure | Placement | Recovery |
| --- | --- | --- |
| Invalid input | Beside the field in its editor | Explain the correction; preserve unsaved input |
| Unresolved event | On the proposal row | Edit relevant details; cannot approve yet |
| Duplicate | On the proposal row, with comparison | Keep existing or deliberately allow a new copy |
| Calendar write | On affected row plus batch summary | Retry only failed rows; preserve receipts |
| AI/network | In the current conversation | Retry, Stop, or choose an explicit service in Settings |
| Account/permission | On account/permission card; task notice if blocking | Reconnect or open the appropriate system setting |
| Bridge/startup | Persistent workspace alert | Reload frontend or open native settings/recovery |
| Interrupted transfer | In transfer result | Explain copy/original state; never silently copy again |

User-facing errors explain impact and next action. Raw HTTP/tool details may appear under Details. Never show credentials or raw request bodies.

## Chat and agent
Display streamed text and meaningful progress, not tool JSON. Questions have up to six wrapped choices plus an alternate typed answer and Cancel. Bind answers to question IDs. Questions and approvals remain in the current conversation. Avoid repeating an already clear destination question. The composer can answer an outstanding question; other commands must not bypass a pending approval.

The backend's validated tools are search_events, read_screen_text, ask_user, create_events, update_event, delete_event and move_events. Improve prompts and tools only with tested contracts. Calendar data and screenshots are untrusted content, not instructions. Extract all relevant dated activities, including appointments, meetings, classes, shifts, travel and deadlines. Use explicit headings and prior answers before asking; group essential questions and keep incomplete rows in the review rather than blocking the batch. Ask only for necessary ambiguity; use tools for facts. Never invent calendar availability, missing values or write success.

## Notch and native surfaces
The notch is a compact task surface, following Design/Notch-reference.png. Completed conversations never open automatically. Collapsing resets conversation, review and source presentation without clearing the task or its receipts; an unfinished event editor stays mounted with its unsaved fields. Reopening hover shows the compact bar. Previous conversation requires an explicit View conversation click. Active questions and pending approval remain actionable. Idle hover opens a 520-point bar (66 points below the camera safe area) with Capture, a command field and optional pop-out. After capture, show a thumbnail, optional instructions and Add to calendar. Working stays compact. Questions, source images, conversation and review expand only when needed, up to 560 points wide and a screen-bounded height. Complete calendar tasks, clarification, field edits, approvals, skips and retries inside the notch using the same native session and validated approval token as the workspace. The full app is optional. Deletes begin unchecked; only a clean, fully selected create batch gets Add all. Never send users to the app just to answer or fix an event. OS permission and account authorization may open their required system/browser surfaces. Notch motion uses a top-anchored eased expansion (220 ms), detail resize (240 ms) and gentle collapse (240 ms), with an 80 ms hover intent delay and 350 ms leave grace. Repeated state snapshots must not restart a transition. Keep expanded content mounted through closing, clip it to the animated shell, fade new content without moving button hit targets, and use immediate transitions for macOS Reduce Motion. Notch controls must respond to the first deliberate click even when another app is active; hover never activates or steals focus. Moving outside the actual panel zone collapses it after the leave grace, including after clicking or typing; keyboard focus must not pin it open. Background questions, approvals and layout updates never open the panel. Activity notifications expire after four seconds even when a review, question or error remains pending; repeating the same task snapshot never extends that lifetime. Hover restores access to the pending task without cancelling or approving anything. Respect display safe areas, multiple displays, keyboard focus and reduced motion.

## Interaction and accessibility
Use labelled buttons, semantic headings, keyboard-accessible inputs, visible focus and status text alongside color. Dialogs trap focus, close with Escape and restore focus. Long lists scroll within sensible bounds. Cmd+Enter approves only the visible current review; Escape must never approve. Disable repeated submission while an action is running and explain disabled states. Motion is subtle and disabled for reduced-motion preferences.

## Acceptance matrix for features
Check empty, processing, awaiting question, awaiting approval, validation errors, duplicates, saving, partial failure, stopped, disconnected, unavailable source, restored history and complete states as applicable. Test a twelve-event list and six long question choices. Real writes require explicit user approval. Use isolated fixture calendars for tests.

## Appearance
+ A single saved preference offers System, Light, and Dark. System must follow live macOS appearance changes, rather than copying its value once.
+ Web colors come from semantic tokens in tokens.css; all portals, forms, account cards, errors and source panels inherit the selected appearance. Preserve contrast in both palettes. Do not add fixed light surfaces for new features.
+ Native windows inherit the app appearance. Do not pin workspace or preferences windows to Aqua/Dark Aqua. Screenshot image content is never recolored. The physical notch/compact status bezel stays black; its expanded quick menu uses the selected appearance.

## Sidebar collapse
The visible toggle beside the Calshot brand switches between the full sidebar and a 64-point icon rail. It stays reachable in every section and both states. Collapsed navigation retains accessible names, hover titles, selected state, calendar readiness and Capture. Recent task labels hide to make room; History remains reachable. The preference is saved natively under sidebarExpanded and restored on launch. Collapsing must not reset the active conversation or calendar review.

## Settings and calendar browsing
Settings groups are General (account, appearance, capture), Calendar accounts (connections and default destination), Friends & sharing, AI service, and Privacy & permissions. Connection setup lives in Settings. Follow the updated Calshot.html Calendar board: Week is the default, with Day/Week/Month controls, a compact month/year toolbar, previous/next and Today, an Ask Calshot field and a blue + for a new event. The sidebar holds the mini month and colored source-calendar checkboxes; visibility never changes the write destination. Use an hourly timetable with a separate all-day row, red today/current-time indicators, and colored event blocks. Lay out overlapping events in lanes; preserve overnight coverage, recurring occurrences and all-day end exclusivity. Begin at 8 AM–8 PM and extend the scrollable range when actual events fall outside it. Month uses event chips and opens a day or event without a permanent agenda column. Event details open in a compact accessible card near the lower-right corner. New event collects explicit date and time/all-day intent, then sends a request through the existing native agent review; never auto-approve. Calendar questions and the + form start a fresh native task, with a new history record and no previous screenshot/transcript attached. Assistant composer messages remain follow-ups in their existing task. Validate origin, text and idle state before clearing any previous task; preserve saved history and receipts. Block new calendar commands while an existing task awaits action. Two-finger horizontal swipes over the board navigate one day, week or month according to the current view. Keep vertical scrolling, ignore zoom gestures and modal dialogs, and limit a gesture plus its momentum to one navigation. At compact widths put the question field on a second toolbar row; keep all navigation and view controls reachable. Use semantic appearance tokens in both themes. Browser data comes from bounded native reads using existing adapters. Keep loading, empty, per-calendar failures and truncation visible, ignore stale responses and never label failed reads as current or free time. Add a calendar, the readiness link and Manage calendar accounts open Settings → Calendar accounts. Friend calendars appear in a separate read-only sidebar group. Friends & sharing opens its Settings section. Only real accepted incoming grants populate production; fictional people belong only in isolated previews.

## Accounts and sharing backend
Supabase is the backend for Calshot accounts, invites and calendar-sharing grants; see Backend/README.md for the implemented contract and integration status. Provider credentials, native approval receipts and the existing agent stay in Swift. A Calshot account is distinct from a connected Google/iCloud/Outlook calendar account. Do not silently publish calendars when connecting an account or asking a question.

Sharing offers Free/busy, Event titles and Full details, enforced on the server before returning or searching event data. Link invitations require sign-in, expire, and bind to one recipient; explain that anyone possessing an unredeemed link can accept it. Never imply an email was sent when only a link was created. Show selected source calendars, last successful sync and coverage. Stale or incomplete friend data must not imply free time. Permission downgrades and revocation invalidate visible friend details and future agent reads. Keep sign-in, sharing, per-calendar sync and invitation errors beside their affected controls. An unconfigured backend is a setup state, not an empty friends list or successful account connection.

## Account entry and onboarding
Use shared workspace tokens for sign-in, signup, email confirmation, password reset and calendar onboarding. Swift owns Supabase Auth/PKCE/refresh and stores sessions in Keychain; snapshots expose only account identity and status. Credentials are unsaved form input and never persisted in JavaScript. Gate workspace, shortcuts and write approval until sign-in and calendar onboarding complete. Hide local history/capture/account lists in signed-out snapshots. Reuse connected calendar sources and request provider/OS consent for missing access. Keep Calshot identity, calendar consent and AI billing routes distinct. Offer only Google and email account sign-in. ChatGPT plan authorization belongs exclusively to AI setup after account sign-in. Place authentication errors in the form, calendar errors by the affected connection, and preserve email on failure. Sign-out cancels idle sessions and gates all native actions without deleting local history or completed writes.

The account boards in Calshot.html define the split illustration/form sign-in layout and provider-aware onboarding (AI assistant, Calendar confirmation, Screen Recording, Shortcut, Ready). Reuse the existing native routes for every action; step position is presentation state. Permission indicators come from actual macOS checks, never a clicked demo toggle. Require an available calendar before completing onboarding. Keep password recovery and email confirmation within the same visual shell. Preserve native password requirements even when reference copy differs. Omit unsupported Apple identity, launch-at-login and friend-invite controls until their native/backend contracts exist; never copy demo successes or placeholder legal links into production. Google account identity and Google Calendar consent remain distinct.


## Personal account sync
Settings → General shows Account & sync, profile, status, last success, persistent error and Sync now. Profiles, appearance/sidebar preferences, account labels and task history are private to the Supabase user; screenshot images and credentials stay local. Saved accounts from another device need local authorization; route them to existing Calendar accounts or AI service settings. Never label metadata as working access. Billing routes, calendar IDs and macOS permissions stay device-local. Sync never replays writes or applies old-account/store responses. Tombstones prevent resurrection; concurrent history edits retain both versions. Separate local history per account and preserve one-time migration backups. Live approvals stay on the originating device.

The entry screen offers Google and email account sign-in only. After signup, require AI setup (ChatGPT plan or API key), then calendar confirmation, Screen Recording, Shortcut and Ready. ChatGPT plan authorization never creates a Calshot account. Returning users preserve their saved settings and billing route. Native validation gates calendar setup and completion behind confirmed AI setup. No automatic Google Calendar OAuth prompt may appear ahead of AI setup.

Supabase owns verified-email identity linking. Google and email logins returning the same canonical Supabase user ID load the same profile, cloud state and local account folder, independent of provider. Never identify, merge, or authorize accounts using an email string from JavaScript, a decoded plan token or user metadata. Preserve current-server UID even when two supplied emails appear equal. Show login/plan/connection errors at the affected step, preserve unsaved API input on failure, and keep credentials in Keychain. Use ChatGPT plan and Save/use API key are explicit billing choices. Do not offer a pre-login AI connection as if it creates a Calshot account.

## Public website and cloud access
The website reuses WebUI tokens but is a separate authenticated client. Its server verifies Supabase identities and exposes read-only task history and explicitly selected cloud calendar data; native capture, AI secrets and write approval remain in the Mac app. Keep website sessions and provider credentials server-side. Distinguish cloud connections from device-only labels; connecting never publishes or shares a calendar. Show missing setup, consent cancellation, stale/out-of-range coverage, partial failures and interrupted sync beside the affected connection/view. Count completed actions only from saved receipts. Never replay a restored task. Website calendar writes and web agent controls require a shared approval contract before being offered.

Mac calendar web sync is a per-calendar opt-in in Calendar accounts. Explain that titles, dates/times and locations upload privately for the past seven and next 55 days; updates require the Mac app to run. Reuse the existing calendar readers and show read-only sources too. Never upload merely on sign-in, calendar discovery or history sync. Supabase selections/generations are authoritative: website Stop syncing clears the cache and invalidates late uploads; re-enabling is explicit in the Mac app. Preserve prior snapshots on failed/incomplete reads with persistent per-calendar errors. Show source Mac, last sync, stale/coverage status on the web; no event writes or friend publication. Do not infer that matching calendar names across Macs represent the same source; users should select one originating Mac per calendar.

The website workspace imports the shared Sidebar, CalendarSidebar, CalendarPage, calendar presentation context, UI primitives and styles directly from WebUI. Do not recreate these as a separate website design. Presentation components receive explicit command/capability props; they never import the native bridge. The web shell supplies verified owner-scoped server reads and shows explicit Mac handoffs for unsupported capture, AI or write actions. Keep credentials and write approval in their existing owners.

The expanded sidebar has a draggable divider (184–320 points), with arrow-key resizing and Home/End bounds. Double-click resets to 228 points. Native snapshots own the saved device width. Keep the workspace drawn through the transparent titlebar, with the standard traffic lights. A transparent native 24-point top drag strip starts after the traffic lights; use it for window movement without intercepting the sidebar divider or content controls. Preserve native edge/corner resizing. The closed notch includes a 12-point landing strip below the camera and 24-point horizontal tolerance; hover polling runs in common run-loop modes.

Sign out belongs in Settings → General → Account & sync, beside the signed-in identity and any account error. Keep it out of the workspace sidebar. Reuse native sign-out validation and the website’s existing server action.

## Friends & sharing
Settings → Friends & sharing sends a calendar-sharing request to an exact verified Calshot account email. Select one to twenty local readable calendars; nothing is selected automatically. Each request chooses Free/busy, Event titles & times, or Full event details. Titles/times is the initial unsaved choice. Explain each level before sending, including locations, notes and links for Full details. Requests expire after seven days and require explicit recipient acceptance; accept/decline/cancel/dismiss and stop-sharing actions remain beside the request or friend. Sharing is one-way. Receiving access never shares the recipient’s calendars in return. Show a request count in Settings navigation.

Swift uploads selected calendars through existing bounded calendar readers and account-owned sharing RPCs. Web sync and friend publication stay separate. Publish no hidden fields beyond the strongest current grant or the newly selected access level. Copies cover the past seven and next 55 days; refresh while the source Mac runs. Failed reads preserve the previous copy with a persistent incomplete warning. Show source, coverage, last sync and per-calendar failures. Stop publishing clears the sharing copy and removes its grants without altering original events or private web sync. No setup, login, browsing, or agent question may initiate a publication.

The browser reuses FriendsSettings. It accepts/declines requests and changes or removes existing access via verified server actions. New publication requires the Mac app. Calendar displays friend sources as a separate read-only group; never offer the change-event control for a friend event. Metadata and permission changes clear old visible event content before reloading. An offline sharing service is an unverified state, never an empty/current schedule.

The agent uses list_friends then search_friend_events with canonical friend IDs and explicit dates. Search rechecks accepted grants and projects permission before filtering. Friend event IDs never enter native write-target lookup. Check stale, complete, truncated, error and coverage fields before discussing availability; missing coverage is not free time. Friend-derived tool outputs and subsequent replies carry an optional backwards-compatible history marker. Keep historical answers visible, but omit marked content from subsequent model memory, including account-synced history. No question sends invitations, changes sharing access, or writes a friend’s calendar.

## Software updates
Settings → General shows the installed version/build, last check, current status, persistent update errors, Check for updates, and device-local automatic check/download preferences. Swift owns Sparkle, preferences, signed feed verification and installation; the website has no Mac updater controls. Release builds check every six hours, download verified updates and install on quit by default. Development builds check manually. Never approve, cancel or replay calendar work for an update. A requested relaunch waits for capture, agent, questions, reviews, writes, connection setup and sync to finish; gate new work during the actual relaunch. Keep update progress and release notes in Sparkle’s native update flow.

## Distributed setup

Google Calendar connection uses Calshot’s registered desktop OAuth client with native PKCE and loopback/state validation. A private-source, authenticated stateless exchange keeps app registration credentials on the server; provider access/refresh tokens return only to Swift and stay in Keychain. Consumer onboarding, Settings and native recovery never ask for Google client IDs or secrets. Offer Internet Accounts as an explicit alternative; explain enabling Calendars and refreshing, and reuse the existing EventKit connection. Preserve existing local/custom account decoding; connecting a calendar never changes Calshot account identity. Cancellation and account changes invalidate pending exchange results.

Screen Recording setup opens the macOS privacy pane with a small native helper containing a draggable file URL for the running app, Show in Finder, Open Settings and Check access. Access status comes from CGPreflightScreenCaptureAccess; dragging does not grant access. Explain the switch, + fallback, quit/reopen and removal of stale entries after ad hoc updates. Reuse this route in onboarding, workspace errors, settings and notch.

The Screen Recording helper is a compact Calshot panel that follows System Settings without requesting Accessibility access. It hides while another app is in front, closes when Settings closes, and pauses tracking during a native app-file drag. Show in Finder and Open Settings remain available for keyboard/manual setup. Its native palette reads the packaged shared CSS tokens. PermissionFlow-derived interaction code retains its MIT notice.
